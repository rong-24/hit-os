## 1. 请简述 `head.s` 的工作原理

*按照代码运行的顺序，叙述 `head.s` 完成了哪些关键工作。*

- 工作 1：进入保护模式所需的最小环境

  - 构造并加载 GDT：为代码段、数据段、TSS 等建立段描述符，装载到 `gdtr`，为后续使用段机制和特权级打基础。  
  - 初始化 IDT：预留中断向量表空间并装入 `idtr`，保证 CPU 进入保护模式后有合法的中断入口。  
  - 设置 `CR0.PE` 进入保护模式：在完成 GDT/IDT 准备后，修改 `cr0` 的 PE 位，从实模式切换到保护模式。

- 工作 2：底层硬件初始化

  - 编程 8253 定时器：设置时钟中断频率，为后续简单调度提供“时间片”来源。  
  - 初始化 8259A 中断控制器：设置主从 PIC 的屏蔽字和中断向量偏移，使外设中断能正确映射到 IDT 中的入口。

- 工作 3：任务与特权级环境搭建

  - 建立 TSS 与 LDT：为 task0 / task1 建立对应的 TSS 和 LDT 描述符并填充内容，确保任务切换时可以自动保存/恢复寄存器和段寄存器。  
  - 准备用户态代码段与栈段：为 ring3 任务准备好代码段、数据段描述符以及初始栈顶地址，为从内核态“跳”到用户态做铺垫。

- 工作 4：从内核态“跳”到用户态并提供系统调用入口

  - 通过构造栈帧 + `iret` 首次进入用户态：在内核栈上压入未来用户态的 `SS:ESP`、`EFLAGS`、`CS:EIP`，再执行 `iret`，一次性完成特权级切换与控制流转移。  
  - 设置 `int 0x80` 系统调用入口：在 IDT 中为 0x80 号中断填入门描述符，使用户态可以通过 `int 0x80` 进入内核，完成最基本的系统调用机制。  
  - 在时钟中断处理函数中切换任务：时钟中断到来时，通过 TSS 切换在 task0 和 task1 之间轮转，实现最简单的时间片轮转调度。

## 3. 简述 `head.s` `57` 至 `62` 行在做什么？

```assembly
pushl $0x17
pushl $init_stack
pushfl
pushl $0x0f
pushl $task0
iret
```


（1）压栈的数据与寄存器对应关系
|     数据      | 对应寄存器 |
| :-----------: | :--------: |
|    `$0x17`    |SS（栈段寄存器）            |
| `$init_stack` |ESP（栈指针寄存器）            |
|   `pushfl`    |EFLAGS（标志寄存器）            |
|    `$0x0f`    |CS（代码段寄存器）            |
|   `$task0`    |EIP（指令指针寄存器）            |


- `pushl $0x17`：先把用户态将要使用的栈段选择子压入栈中，指定后续任务在 ring3 所使用的栈所属段。  
- `pushl $init_stack`：压入用户态初始栈顶地址，将来会装载到 `ESP`。  
- `pushfl`：把当前 `EFLAGS` 入栈，保证切换之后仍然沿用合适的标志位状态。  
- `pushl $0x0f`：压入用户态代码段选择子。  
- `pushl $task0`：压入用户态程序的入口地址。  
- `iret`：CPU 从栈中依次弹出 `EIP`、`CS`、`EFLAGS`、`ESP`、`SS`，完成一次“伪中断返回”。

这几条指令的核心目的，是**手工伪造一个“中断返回现场”**，借用 `iret` 的硬件语义来完成从 ring0 到 ring3 的首次跳转。  
在保护模式下，不能直接给 `CS`、`SS` 赋新值跨特权级，只能通过中断门 / 调用门 / 任务门等机制完成。通过在内核栈上构造完整的返回现场，再执行 `iret`，CPU 认为是在处理一个“从内核返回到用户态”的中断，于是自动完成特权级检查、段描述符装载和栈切换，从而安全地进入用户态的 `task0`。







## 4. 简述 `iret` 执行后， `pc` 如何找到下一条指令？

`iret` 的执行过程大致如下：

1. CPU 从当前栈顶开始，依次弹出 5 个双字：  
   - 第 1 个装入 `EIP`，作为返回地址；  
   - 第 2 个装入 `CS`，同时从 GDT/LDT 中取出对应段描述符，更新隐藏部分；  
   - 第 3 个装入 `EFLAGS`；  
   - 如果发生特权级切换（例如从 ring0 到 ring3），再弹出 2 个双字分别装入新任务的 `ESP` 和 `SS`。  

2. CPU 检查 `CS` 选择子的 RPL 与目标段描述符 DPL，确认此次返回是否合法，同时更新 CPL（当前特权级）。  

3. 通过新的 `CS:EIP` 组合形成线性地址，到内存中取出指令字节。  

4. 从这一地址开始继续流水线取指，`pc`（在 32 位下就是 `EIP`）因此指向了我们在栈中预先压入的 `task0` 入口处。

整个过程完全由硬件按照 `iret` 的语义完成，软件只需要事先把想要跳转到的位置和段信息压入栈中。






## 5. 记录 `iret` 执行前后，栈是如何变化的？

*首先，粘贴 `bochs` 查看相关信息的截图*。

![iret_before](.\images\iret_before.png)
![iret_after](.\images\iret_after.png)

*之后，简述过程以及发生变化的原因。*

- **执行前**：  
  在内核栈顶，依次压入了未来用户态要恢复的 `SS`、`ESP`、`EFLAGS`、`CS`、`EIP` 五个双字。此时 `ESP` 指向 `SS` 这一项的起始位置，栈中还保留着之前内核执行时的局部变量、保存现场等内容。  

- **`iret` 执行时**：  
  CPU 按照 `iret` 的规则，从栈顶依次弹出这些值并写回对应寄存器：  
  1. 弹出 `EIP` 和 `CS`，形成新的 `CS:EIP`，准备作为返回地址；  
  2. 弹出 `EFLAGS`，恢复中断允许位等状态；  
  3. 因为从 ring0 切换到 ring3，继续弹出 `ESP` 和 `SS`，切换到用户态栈。  

- **执行后**：  
  内核栈上的这 5 个双字被弹出，`ESP` 回到了构造栈帧之前的位置；CPU 的当前栈改为用户栈（`SS:ESP = 0x17:init_stack`），接下来的栈读写都发生在用户态空间中。`EIP` 已经指向 `task0` 的入口，开始执行用户代码。  

栈之所以发生这样的变化，是因为 `iret` 用来“恢复被中断现场”，而特权级切换又必须通过这种恢复机制来完成。我们在内核中主动伪造了一个“中断前的用户态现场”，于是 `iret` 就把 CPU 从内核栈“拉回”到了我们构造好的用户态现场。




## 6. 当任务进行系统调用时，即 `int 0x80` 时，记录栈的变化情况。



![0x80_before](.\images\0x80_before.png)
![0x80_after](.\images\0x80_after.png)





- **触发系统调用（`int 0x80`）前**：  
  CPU 正在用户态执行，使用的是用户栈（`SS = 0x17`）。栈中主要保存着用户函数调用产生的返回地址、局部变量等信息，`EIP` 指向当前执行的用户指令。  

- **执行 `int 0x80` 时**：  
  1. CPU 查找 IDT 中 0x80 号描述符，发现是一个从 ring3 到 ring0 的中断门；  
  2. 从当前任务的 TSS 中取出内核态栈指针 `SS0:ESP0`，切换到内核栈；  
  3. 在**内核栈上**依次压入用户态的 `SS`、`ESP`、`EFLAGS`、`CS`、`EIP`，形成完整的中断现场；  
  4. 将 `CS:EIP` 修改为系统调用入口（内核中的 `system_call`）、CPL 变为 0。  

- **系统调用返回时**：  
  系统调用处理函数在结束前会执行 `iret`，从内核栈中按相反顺序弹出 5 个双字，恢复用户态的 `EIP`、`CS`、`EFLAGS`、`ESP`、`SS`，重新切换回用户栈并接着执行下一条用户指令。  

栈之所以需要这样大幅度变化，是因为**用户态与内核态必须使用不同的栈**。在进入内核时，把用户态的现场完整保存在内核栈上，可以保证：

1. 内核代码运行在自己的受保护栈空间内，不会被用户程序破坏；  
2. 系统调用完成后，只要执行一次 `iret`，就能严格按照原样恢复用户程序的执行状态，实现“看起来像一次普通函数调用”的系统调用效果。






## 总结与反思

通过本次对 `head.s` 的单步调试，我把课本上抽象的“进入保护模式”和“特权级切换”真正落到了寄存器和内存的具体变化上。  
从构造 GDT、IDT 开始，到设置 CR0 的 PE 位，再到用伪造栈帧 + `iret` 完成从内核态到用户态的第一次跳转，以及通过 `int 0x80`/`iret` 在用户态与内核态之间往返，我对 x86 架构下操作系统启动的关键路径有了系统而直观的认识。  

实验的难点主要集中在理解 `iret`、`int 0x80` 执行时自动压栈 / 弹栈的顺序，以及 Bochs 中各寄存器与内存状态之间的对应关系。多次配合截图反复单步之后，我逐渐能“预判”下一步栈会长什么样，这也提高了自己分析底层 bug 的能力。  

这个简化的 Linux 0.00 引导程序虽然规模不大，但已经包含了现代操作系统的核心机制雏形，例如段机制、特权级、任务切换与系统调用。理解这一部分，为后续进一步学习分页管理、进程调度和文件系统等内容打下了坚实的基础。
